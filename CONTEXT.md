# LLM Server

Docker-стек локального LLM-инференса: единый маршрутизатор llama-swap
(`http://localhost:8080`) с двумя взаимоисключающими движками (llama.cpp и
NInfer) на двух NVIDIA GPU по 16 ГиБ. Публичный контракт — один model-ID
`qwen3.8-27b`; активный профиль llama-swap выбирает движок, переключение
только ручное. Решение — ADR-0006. Отдельный compose-профиль `vllm` остался в
репозитории, но выведен из текущей топологии.

## Language

**Маршрутизатор**:
llama-swap: процесс, который принимает запросы на `:8080`, держит конфигурацию
публичных model-ID и запускает нужный движок как дочерний процесс. Один
контейнер (`llama-swap`, образ `router:v265` из `router/Dockerfile`) с обоими
движками внутри.
_Avoid_: прокси, шлюз, бэкенд

**Профиль**:
Активный профиль llama-swap (`llama` или `ninfer`): определяет, какой движок
стоит за единым model-ID. Переключается вручную
`PUT /api/profiles/active {"name":"llama"|"ninfer"}` (или UI). Не путать с
compose-профилем: у сервиса роутера compose-профилей больше нет (compose-профиль
`vllm` — единственный оставшийся и он вне текущей топологии).
_Avoid_: режим, compose-профиль

**Движок**:
Программа, которая держит модель в VRAM и обрабатывает запросы: `llama-server`
или `ninfer-serve`. Запускается llama-swap как дочерний процесс через `cmd`;
движки никогда не работают параллельно (дефолтная exclusive-группа).
_Avoid_: runtime, бэкенд

**Backend-модель**:
Внутренняя запись движка в конфиге llama-swap (`backend-llama`,
`backend-ninfer`): `unlisted: true` (не видна в `/v1/models`) и закрыта пином
`~` в неактивном профиле — прямой запрос к неактивному движку даёт `404`.
_Avoid_: бэкенд, модель

**Пин**:
Запись профиля llama-swap, связывающая публичный model-ID с backend-моделью
(`qwen3.8-27b` → движок) или запрещающая backend-модель (`~`). Пины
применяются до алиасов; селекторов нет, поэтому никакой запрос клиента не
запускает swap.
_Avoid_: маппинг, привязка

**Публичный model-ID**:
Строка, которую клиент передаёт в поле `model` запроса и видит в `/v1/models`.
Ровно один — `qwen3.8-27b`; алиасов-режимов больше нет (ADR-0006). Синтетическая
запись пина всегда показывает `status: unloaded` (hardcode llama-swap для
пинов) — правдивое состояние движка смотрите в `/api/profiles`.
_Avoid_: имя модели, идентификатор модели

**Дефолт шаблона**:
Поведение голого запроса (без reasoning-полей): chat template артефакта даёт
thinking on + effort `xhigh` на обоих движках. Серверного мнения о reasoning
нет — режим задаёт клиент.
_Avoid_: instruct-режим, серверный режим

**Reasoning-контракт**:
Переносимый способ управления reasoning от клиента (проверен на обоих
движках): выключить thinking — `chat_template_kwargs: {"enable_thinking":
false}`; уровень — `reasoning_effort: low|medium|xhigh` (top-level или в
kwargs). Top-level `none` выключает thinking только на NInfer (на llama.cpp
инертен). Невалидное значение → `500` (llama.cpp) / `400` (NInfer).
_Avoid_: уровень reasoning, режим reasoning

**Безопасное подмножество**:
Набор полей запроса, безразличных обоим движкам (сводка отчёта 0013, таблица в
ADR-0006): sampling-поля в переносимых диапазонах (`top_k` не 0),
`reasoning_effort` из `none|low|medium|xhigh`,
`chat_template_kwargs.{enable_thinking, preserve_thinking}` (bool). Вне
подмножества: `repetition_penalty` (стрипается llama-swap), `repeat_penalty`
(llama.cpp-only), `top_k: 0`, NInfer-несовместимые фичи.
_Avoid_: общий словарь, контракт sampling

**Пресет sampling**:
Серверный дефолт сэмплирования, живущий в `cmd` движка: CLI-флаги llama.cpp в
`router/config.d/10-llama.yaml`, mode-aware пресет NInfer. Поля запроса его
перекрывают.
_Avoid_: режим сэмплирования, setParamsByID

**Артефакт модели**:
Файл с весами в формате конкретного движка: `.gguf` для llama.cpp, `.ninfer`
для NInfer, каталог safetensors для vLLM. Артефакт NInfer — единый файл,
содержащий текстовый транк, Vision, MTP и DFlash2-драфтер.
_Avoid_: веса, чекпоинт, модель

**Загрузка GPU**:
Доля физической VRAM, занятая моделью и KV-cache. На GPU1 (графическая
сессия) под пиковой нагрузкой должно оставаться не менее 512 MiB свободно
(красная линия).
_Avoid_: утилизация, utilization

**Полоса**:
Один одновременно активный запрос у движка при `--max-concurrency N`: decode
у двух полос идёт параллельно, но префиллы сериализуются. Число полос не
равно числу запросов — лишние встают в очередь движка.
_Avoid_: lane, конкурентный запрос
