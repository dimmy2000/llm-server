# Бенчмарки: три модели через :8080

Одноразовый прогон бенчмарк-набора [llm-bench](https://github.com/Grigory-Rylov/llm-bench)
(коммит `bde1a227d022f7a25ac6e673f567aee1c7220ea4`, 2026-11-11; прогоны —
**2026-11-17**) для трёх публичных моделей роутера (`http://localhost:8080`):
`qwen3.8-27b` (NInfer v0.4.6, TP=2), `strata-iq3` (Strata 0.1.45, IQ3_XXS @131k),
`strata-iq2` (Strata 0.1.45, IQ2_XS @262k). Все замеры — через роутер, единую
точку входа. Числа взяты из полных stdout прогонов (`.scratch/llm-bench-results/assets/run-*/`),
сводки тикетов 05/06/07 карты `.scratch/llm-bench-results/` — вторичны.

## Среда

| Параметр | Значение |
| :--- | :--- |
| Роутер | llama-swap v265 (exclusive-группа: unload → start), образ `llm-server/router:v265-strata1-nollama` |
| Движки | NInfer v0.4.6 TP=2 (DFlash2, `--max-context 262144`), Strata 0.1.45 |
| Модели | `qwen3.8-27b` — NInfer, Qwen3.8-27B NVFP4 + DFlash2-drafter, ctx 262144; `strata-iq3` — IQ3_XXS, ctx 131072; `strata-iq2` — IQ2_XS (native-ID `qwen3.8-flash-next-iq2_xs`), ctx 262144 |
| Железо | 2× RTX 5070 Ti 16 GiB (GPU1 — дисплейная, красная линия ≥ 512 MiB), 59 GiB RAM |
| Драйвер хоста | open-модули `615.71.09-p2p` (форк `aikitoria/open-gpu-kernel-modules`), NInfer TP=2 идёт по P2P |
| Thinking | выключен (`chat_template_kwargs.enable_thinking: false` — свойство бенч-скриптов) |
| Режим | ровно один резидентный движок; свап платит первый запрос (впитывается warmup) |

## Протокол

- Промпты — реальный текст (Project Gutenberg), чанки взаимно непересекающиеся:
  ни один замер не обслуживается контекст-кэшем другого (проверяется по
  `cached_tokens`/`cache_n`).
- **Prefill** (`bench-real-prefill.sh`): 3 прогона на глубину (у каждого — свой
  чанк) + decode-пробник (~128 токенов, 3 прогона). Глубины:
  `qwen3.8-27b`/`strata-iq2` — 40k/150k/200k; `strata-iq3` — 40k/120k
  (контекст 131072). `RUNS=3`, decode-пробник — дефолты скрипта.
- **Параллельный декод** (`bench-parallel-decode.py`): solo (2 прогона) против
  `--concurrency 2` (3 прогона, канонический `--chunk-offset 100` → слоты
  100–105), чанки 40k, разнесённые слоты против кэша. В тех же вызовах
  делался бонусный par-прогон (слоты 0–3) — он вне канона, в таблицы не входит.
- FLUSH-шаг prepare выключён (`FLUSH=0`): через роутер он не работает, кэш
  вытесняет per-depth warmup prefill-скрипта. `MODEL`/`--model` задан ЯВНО для
  каждой модели (в `/v1/models` алфавитный порядок, дефолт скриптов — первый ID,
  то есть `qwen3.8-27b`).
- Пин клона llm-bench `bde1a22` + два однострочных sed-патча рабочей копии
  (обязательны для работы через роутер; полный diff —
  `.scratch/llm-bench-results/assets/04-clone-patch.diff`):
  `"bench-prepare"` → `"qwen3.8-27b"` в `bench-real-prefill-prepare.sh` и
  `make-chunks.py`; `depth // 12 + 1` → `depth // 15 + 1` в `bench-real-prefill.sh`
  (warmup глубины 120k иначе не влезает в ctx 131072 iq3).

## Источник метрик

tok/s везде **engine-side**: у всех трёх движков в стриме есть блок `timings`
(`prompt_n/prompt_ms`, `predicted_n/predicted_ms`, `draft_n/draft_n_accepted`,
`cache_n`) — для NInfer это подтверждено живым прогоном в тикете 01 (стрим
`ninfer-serve` отдаёт `usage.prompt_tokens` и полный `timings` той же схемы,
что у Strata) и прогоном тикета 05. Клиентские скорости (`prompt_tokens`/TTFT)
в stdout не выводились; значимых `timings`-пропусков не было ни в одном ране,
поэтому ни одно число ниже не требует пометки `*` (client-side).

Сумма потоков (mean по прогонам) — то, что реально даёт конкурентность при одном

(exclusive-группа, один движок). У NInfer картина иная: поток, закончивший

«на поток» (14.3–135.4) при росте суммы потоков. MTP accept: iq3 solo 59.2–78.7%,
c2 61.3–74.7%; iq2 solo 65.5–69.2%, c2 58.9–73.6%; qwen solo 19.4–20.0%,
c2 по ранам 17.5–24.8%.

Бонусные par-прогоны (в тех же solo-вызовах, слоты 0–3) для теплоты: qwen
агрегат 15.0, сумма потоков 119.6; iq3 12.8, сумма 234.7 (117.4 на поток);

## Условия прогонов

- **Кэш-контаминация: 0.** Во всех канонических цепочках `cached=0/0` и
  `cache reuse clean` в каждом замерном ране prefill и decode-пробника;
  ожидаемого малого `cached_tokens ~10–50` на первом замере глубины не было —
  warmup вытесняет кэш полностью. Parallel-скрипт per-stream `cached` не
  печатает: чистота по построению (тексты слотов 0–3 / 100–105 / 200–201 не
  пересекаются с prefill-чанками). Warmup-запросы parallel-скрипта видны в окне
  роутера как два `done: 2 tokens in 0 s` (16:16:49Z, 16:17:48Z) — замерные ранги
  не затронуты.
- **Контаминированные попытки strata-iq3 в таблицы не попали.** Первая попытка
  (`assets/run-strata-iq3/attempt1-swap-race/`, свап-гонка: агент рассуждал
  моделью `qwen3.8-27b`, пока бенч крутил `strata-iq3`) испортила четыре TTFT-рана
  (120k run-1 57 452 и run-3 58 080 ms при чистом run-2 26 094; 40k dec-1/dec-2
  32 801/32 901 ms): 120k TTFT mean 47 208 ms вместо чистых 25 930; в rerun
  испорчен run-3 (85 778), mean 45 884; третий проход 120k — 92 443/97 269 ms.
  Промежуточные цепочки (`assets/run-strata-iq3/interleaved/chain1-3`, те же
  рассуждения на том же движке): chain2 40k TTFT 43 094/51 017 ms (mean 34 329),
  chain3 c2 aggregate mean 8.6 (раны 6.5/6.5/12.8) вместо 12.9. Engine-метрики тех
  попыток чистые (40k 4 489.9/4 472.6, 120k 4 606.1/4 630.5 tok/s, 1–4% от
  канона): очередь движка портит TTFT, но не скорость префила. Канон iq3 —
  цепочка chain4, 15:49:22Z–15:55:30Z UTC (`run-times.txt`), в окне роутера
  только запросы бенча.
- **Свап-эпизоды — вне окон замеров.** Ни в одном каноническом окне не было ни
  одной строки загрузки/выгрузки весов: iq2 был резидентен с 19:06:06 MSK
  (холодный старт впитался до бенча), свапы iq3↔iq2 16:04:09Z–16:06:06Z и
  переход iq3→qwen→iq3 в 15:42:17Z случились до/вне замерных окон; qwen3.8-27b
  резидентна (прелоад), свап не платился. Постоянного свопа нет: swap used
  322 → 319 MiB (qwen), 318 → 318 MiB (iq3, iq2). RAM: 8 344 MiB available при
  резидентном iq3 (page-locked эксперты ~47 GiB), 17 167 → 16 969 MiB при iq2,
  52 632 → 51 318 MiB при qwen.
- **Корпус текста:** 6 книг Project Gutenberg, ~3.3M токенов, чанки в
  `realdata/chunks` клона llm-bench (36 файлов: 18×40k — a,b,c,d1–d3 и числовые
  слоты 0–3, 100–105, 200–201; по 6 чанков 120k/150k/200k). Чанки 40k/120k
  общие для iq3 и iq2 (ptok mean 40 008 совпадает); у qwen 40k — другой текст
  той же номинальной глубины (ptok mean 39 952), это надо учитывать при
  сопоставлении TTFT 40k между движками.

### Оговорки метода

- `prompt_tokens` qwen сняты пост-пробами (в QUIET-stdout их нет), а не из
  замерных ранов; у strata-ранов measured = manifest − 4 токена (константа
  шаблона: `count_tokens` даёт базу 52, `usage` — 48).
- Габарит чанков в допуске ±0.5% кроме `40000-b` = 39 779 (−0.55%, iq3/iq2).
  В `realdata/manifest.json` записей 150k/200k нет: prepare с `FORCE=1`
  (pass B, глубина 120k) перезаписал манифест pass A; сверка глубин этих двух
  групп — по target-допуску, манифест вручную не чинился (файлы чанков на диске
  полные, 36/36).
- Чанки iq3-канона собраны заново с новых позиций курсора (`prepare-fresh.log`),
  поэтому их `prompt_tokens` отличаются от первой попытки (40 008 против 39 911;
  120 489 против 119 946) — ранее протестированный текст не переиспользовался.
- `decode tok/s` parallel-скрипта — на поток по engine-`timings`; «агрегат» —
  сумма engine-токенов / время самого медленного потока (включает TTFT), поэтому
  при одном резидентном движке конкурентность в агрегате не видна.
- Методические наблюдения прогонов: у всех трёх моделей warmup вытесняет кэш
  полностью (ожидаемого `cached ~10–50` нет), decode-пробник на 200k у iq2 влез
  в контекст (200 471 + 128 < 262 144, SHORT-STOP не сработал ни разу), сбоев
  (FAIL/4xx/5xx/OOM/зависаний) в канонических цепочках не было, exit=0 на всех
  шагах.
