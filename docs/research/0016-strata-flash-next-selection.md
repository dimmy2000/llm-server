# 0016 — Strata (Qwen3.8-Flash-Next): выбор размера для постоянного использования

Дата: 2026-10-19. Статус: решено (условное — финальная ротация по пилоту на рабочих задачах).
Карта усилия: `.scratch/strata-model-selection/map.md`; сырые данные —
`.scratch/strata-model-selection/assets/`; протокол — `issues/06-benchmark-protocol.md`;
свод матрицы — `assets/summary-matrix.md`.

---

## 1. Гипотеза

Strata (Qwen3.8-Flash-Next, GDN-гибрид 27B MoE) на 2× RTX 5070 Ti + 59 GiB RAM
может дать decode в разы выше llama.cpp-стека той же модели (репер 20 tok/s),
но связку «размер кванта ↔ RAM 59 GiB ↔ контекст» нужно измерить на живом
железе. Вопрос отчёта не «быстрая ли Strata», а **какой размер держать постоянно**
(и подходит ли вообще какой-то).

Замер — вытесняющий режим: основной стек остановлен (`docker compose down`),
Strata нативно на `:8081`, обе карты. Это режим эксперимента, не эксплуатации;
эксплуатационная интеграция (llama-swap) — отдельное последующее усилие (§9).

## 2. Факты развертывания

- Установка: `/opt/strata`, движок собран на CUDA 13.3 (0.1.44-линейка), конфиги
  `strata-{iq3_xxs,iq3_s,iq2_xs}.json` на `:8081`, `gpus [0,1]`, `gpu_order: as_given`,
  базовый контекст 32768, `--vram-reserve-later-mib` GPU0 300 / GPU1 2048
  (механика красной линии ≥ 512 MiB дисплейной GPU1).
- Три размера скачаны: **IQ3_XXS, IQ3_S, IQ2_XS** (shard2 общий, hard-link).
  UD-IQ4_XS и вся семья UD-Q4_K_XL+ исключены по RAM-бюджету (§8).
- Vision: апстрим-артефакта mmproj для квантов нет — BF16 mmproj квантован локально
  в **Q8_0** (588 MB); энкодер `strata-vision` на CPU — **наш стандарт использования**
  (GPU-эластичный fallback не потребовался ни в одном окне; стоимость VRAM нулевая).
- Нюансы среды opencode (в будущих окнах всегда помнить): запуск с `env -u http_proxy -u https_proxy`
  (прокси ломает bun-fetch даже к `127.0.0.1`), имя провайдера **не** `llama-swap`
  (конфликт с глобальным `:8080`; использовать `strata-s`), всегда `--standalone`.

## 3. Критерии годности (зафиксированы до замеров)

- **Жёстко:** стабильность — матрица без OOM/зависаний/дисковых штормов, RAM без
  постоянного свопа, VRAM GPU1 ≥ 512 MiB.
- Decode > 20 tok/s (репер llama.cpp).
- Контекст — фиксируем по максимуму каждой модели, без порогов.
- Качество — только опубликованные данные + субъективная оценка из агент-сессий.
- Приоритет: IQ3_XXS → IQ3_S → IQ2_XS.

## 6. RAM/VRAM-бюджет и риски

- **IQ3_XXS** (47.0 GB req, 43 GB экспертов): безопасен по RAM; на потолке платит
  лествицу (chunk 4096 / cache 4400) — ~270 MiB VRAM сверх математики на CUDA0;
  VRAM-минимум за весь день 1494 MiB.
- **IQ3_S** (54.8 GB req, 50 GB экспертов): единственная с реальной платой —
  non-resident expert-cache (RAM под загрузкой уходит в page-cache shard'ов,
  min avail 2.9 GiB) из-за апстрим-блокера `--resident-experts` на 2-GPU сплите
  (cuBLAS status 3). Зарегистрированные в community деградации под RAM-пресурой
  (#2923 re-prefill 300K+, #2934 heap, #2316 checkpoint-replay collapse) на этой машине
  не воспроизведены на этой машине; в выбранную схему (без IQ3_S) этот риск не переходит.
- **IQ2_XS** (39.2 GB req, 35.5 GB экспертов): целиком в RAM (min avail 6.0 GiB),
  лучшая VRAM-гигиена обоих карт (GPU0 2103 / GPU1 1605 MiB).
- **Операционный caveat двухмодельной схемы:** XXS и XS не живут резидентно
  одновременно (43 + 35.5 GB экспертов > 59 GiB); переключение = полная перезагрузка
  весов (десятки секунд + page-cache давление). Обе модели перед свапом на
  llama/ninfer требуют останова (VRAM).
- Community-риски, не воспроизведённые у нас, но относимые к нашему профилю
  (см. тикет 04): #1944 (single-token после ~12K на самом 5070 Ti+64 GB, 0.1.42),
  #2408 (OOM на restore long-снапшота 2-GPU — держать `--vram-reserve` щедрым,
  `--conversation-cache-mib` маленьким), CJK-коллапс на длинных выводах (#1827),
  агрессивный thinking (обрыв ответа внутри `</think>` без закрытия → агент молча
  останавливается; задавать `max_tokens` с запасом ≥ 12–16K). Каждая смена версии
  движка — новая точка калибровки и smoke-check кванта (#2457 pattern).

## 7. Открытые апстрим-вопросы (репортить по завершении усилия)

1. `--resident-experts` — блокер движка на 2-GPU сплите (exit в prefill gemm,
   cuBLAS status 3).
2. Калибратор не записывает adaptive-аргументы для IQ2_XS (измерил, не записал).
3. Потолок 88.5 % от заявленного у всех размеров — механика кольца/чанков.

## 8. Исключение: UD-IQ4_XS и семья UD-Q4_K_XL+

Исключены остающимся RAM-бюджетом (зафиксировано картой): экспертам нужно
~72 GB RAM при доступных 59 GiB. Официально описанный SSD-стриминг (`--mmap-experts`) даёт
~7–8.5 tok/s — под порог «полезного» decode. Изменится только при апгрейде RAM
как новое усилие.

## 9. Feasibility интеграции в llama-swap (для следующего усилия)

**Feasible** (тикет 02, по коду llama-swap v265):

- **Основной путь — B2 «shim-модель»:** модель `backend-strata` с `cmd: sleep infinity`,
  `proxy: http://<host>:8081`, `checkEndpoint: /health`. Сохраняет контракт ADR-0006
  (один публичный ID, переключение `PUT /api/profiles/active`), без пересборки образа;
  Strata живёт нативно на `:8081` под systemd/скриптом. «Swap» здесь косметика
  (VRAM/RAM Strata освобождается руками в рамках дисциплины оператора).
- План B — контейнерный `cmd` (честный swap, третий образ-пин + memlock/`unloadTimeout`).
- Дешёвый старт — C: отдельный провайдер opencode (`:8081`) на период верификации.
- B1 (peers) — только если ослабим контракт «exactly one ID».
- Not-go: запуск Strata через hooks (не умеет команд); unix-socket (нет ни у одной из сторон).

## 10. Решение

**Держать постоянно две модели** (схема проверена матрицей, финальная ротация —
по пилоту на рабочих задачах после интеграции):

- **IQ3_XXS @131072 — основная роль:** сложные вопросы, подготовка планов работ,
  постановка задач субагентам. Мотивация: наилучшее публикуемое качество, доступное
  этому железу (84.46 % top-token; выше только IQ3_S, которая не выбрана), при
  decode 129–153 tok/s и потолке, покрывающем длинные агент-сессии.
- **IQ2_XS @262144 — вторая роль:** простые/повседневные задачи как аналог
  Qwen 3.8 27B, где требуется большое окно (~262k). Мотивация: лучший decode
  тройки (144.9/154.7), самый большой потолок, целиком в RAM (min avail 6.0 GiB),
  лучшая VRAM-гигиена; качество не публикуется — приемлемо для роли, где
  субъективная планка ниже.
- **IQ3_S — не выбрана** (прошла матрицу, но по схеме без собственной роли:
  RAM-теснота non-resident 2.9 GiB, апстрим-блокер resident, потолок 65536 перекрыт
  обеими выбранными).
- **Runner-up:** IQ3_S — условный (возвращается в пул при починенном апстрим-блокере
  `--resident-experts` на 2-GPU сплите или ином росте RAM-бюджета).
- **Fallback:** существующий стек Qwen 3.8 27B (llama.cpp/NInfer) — остаётся на месте;
  если пилот забракует роль, она просто возвращается этому стеку.
- **Пересмотр решения — по итогам пилота на рабочих задачах** (критерии качественные,
  §10.1); «никакой не подходит» — снято: обе выбранные прошли все жёсткие критерии.

### 10.1 Критерии пересмотра (пилот)

- **IQ3_XXS (роль сложного):** субъективно заметно хуже 27B-стека на сложных
  планах/постановках → роль возвращается 27B, XXS выбывает.
- **IQ2_XS (роль простого):** субъективно ловимы ошибки качества, которые 27B
  не делает, на повседневных задачах → роль возвращается 27B-стеку.
- **Операционное ограничение:** обе модели не резидентны одновременно (§6) —
  переключение между ролями это полная перезагрузка весов; формальные eval'ы —
  out of scope этой карты.
