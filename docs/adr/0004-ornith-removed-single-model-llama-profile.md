# ADR-0004: Модель Ornith 9B удалена из проекта, llama-профиль оставлен с одной моделью

Status: accepted. Заменяет посылку ADR-0001 о двух моделях llama-профиля.

## Контекст

llama-профиль держал две модели: `ornith-9b` (GGUF Q8_0, 9.3 GiB веса) и
`qwen3.8-27b` (NVFP4-MTP, ~17.6 GB). Они не помещались в VRAM одновременно,
поэтому переключение было ручным: `POST /api/models/unload/:model_id`, затем
запрос к другой модели (`ADR-0001`). Ornith использовался как быстрый
небольшой инструктивный режим (~40–60 tok/s decode) и как отдельный
thinking-режим (`ornith-9b-thinking`, `ornith-9b-instruct`).

Модель устарела и больше не используется. Разрыв совместимости с профилем
`ninfer`, который не умеет GGUF и потому не знал этих ID (ADR-0003, п. 6),
перестал быть проблемой: у быстрых задач остаётся единственный путь —
`qwen3.8-27b` в instruct-режиме.

## Решение

1. Модель `ornith-9b` и её режимы `ornith-9b-thinking` / `ornith-9b-instruct`
   удалены из `llama/config.yaml` вместе со всеми упоминаниями в документации.
   Публичный список model-ID llama-профиля теперь совпадает со списком
   профиля `ninfer`: `qwen3.8-27b` плюс шесть алиасов
   `-chat-{low,medium,xhigh}` и `-agent-{low,medium,xhigh}`.
2. Быстрые задачи, которым был нужен Ornith, обслуживает instruct-режим
   `qwen3.8-27b`. Он не дороже Ornith по задержке: замерено ~106–131 tok/s
   decode (профиль `ninfer`) и ~80 tok/s (llama.cpp) против ~40–60 у Ornith,
   то есть instruct-режим Qwen 27B быстрее. Переключать профили ради быстрых
   задач не требуется, поэтому зависимости от переключения профилей во время
   активной сессии больше нет.
3. Ручное переключение моделей в llama-профиле больше не существует: в
   `llama/config.yaml` включён `hooks.on_startup.preload` для `qwen3.8-27b`
   (единственная модель), прогрев занимает ~40–60 c при старте контейнера,
   а первый запрос сразу обслуживается.
4. Старые публичные ID (`ornith-9b`, `ornith-9b-thinking`,
   `ornith-9b-instruct`) не получают backcompat-алиасов — по тем же основаниям,
   что и в ADR-0002.

## Отвергнутые альтернативы

- Оставить Ornith для быстрых задач и переключать профили/модели вручную:
  держать в проекте устаревшую модель ради режима, который быстрее доступен
  на `qwen3.8-27b`, неоправданно.
- Найти артефакт Ornith для NInfer: модели нет и она не используется.
- Показывать `ornith-9b-*` агентам как «доступно только в llama-профиле»:
  ID не существует ни в одном профиле, показывать его нечего.

## Последствия

- ADR-0001 сохраняет силу в части «модели запускаются llama-swap как
  дочерние процессы `cmd`, отдельный контейнер `llama-server` не нужен»; его
  посылка про две модели и ручное переключение заменена этим ADR.
- Инструкция «в llama-профиле в VRAM помещается только одна модель,
  переключение — через unload» удалена из AGENTS.md и README: в профиле
  теперь одна модель, переключать нечего.
- Внешние потребители, зовущие `ornith-9b-*` (если такие остались), получат
  ошибку `model not found`; миграция на `qwen3.8-27b` тривиальна (instruct) или
  на `qwen3.8-27b-agent-*` (thinking с сохранением reasoning).
- Профиль `vllm` не затронут: он никогда не знал `ornith-9b-*`.
