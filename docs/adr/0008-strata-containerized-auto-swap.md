# ADR-0008: Strata в роутер-контейнере — автоматический swap трёх ID без ручных шагов

Status: accepted (2026-10-19; верифицирован 2026-10-20, тикет 11).

Supersedes ADR-0007 в части механики подключения и способа переключения
(нативный юнит + `strata-use.sh` демонтированы). Данные ADR-0007 о размерах,
RAM-физике и клиентском контракте страта-ID остаются в силе.

## Контекст

ADR-0007 дал работающий, но непригодный для рабочих задач вариант: strata-ID
(`strata-iq3`/`strata-iq2`) были shim-моделями к нативной Strata на хосте,
а последовательный доступ обеспечивался внешним оркестратором
`scripts/strata/strata-use.sh`. Пилот первой итерации зафиксировал это как
главный UX-обрыв: выбор модели в клиенте не работал, перед каждой сессией был
нужен ручной шаг со sudo, плюс система рассинхронов «профиль ↔ резидентный
размер» с 404-ловушками пин-семантики v265.

Дестинация переработки (карта `.scratch/strata-integration/map.md`, гриллинг
2026-10-19): **полный автомат** — любой запрос к любому из трёх публичных ID
сам приводит систему в нужное состояние; ручных шагов нет — ни скрипта, ни
sudo, ни `PUT` как обязательного пути. Контракт клиентов не меняется.

## Решение

### 1. Движок Strata — обычный ребёнок llama-swap в роутер-контейнере

llama-swap v265 запускает Strata как обычный `cmd`-бэкенд (третий движок в
контейнере роутера, «ровно как qwen») — без docker.sock, без шимов, без
вмешательства на хосте:

- Сборка: build-стадия `strata-build` в `router/Dockerfile` по upstream-пути
  `/opt/strata/Dockerfile` (исходники — additional context `strata-src=/opt/strata`
  в build, `CUDA_ARCHITECTURES=120`); в рантайм-стадию идут бинарники `engine/`,
  `serve/`, `tools/` и venv движка; для контейнерного `strata-vision` в образ
  добавлен `libnccl.so.2` из devel-базы. Образ — `llm-server/router:v265-strata1`,
  в нём llama-swap v265, llama.cpp b10438, NInfer v0.4.6 и Strata **0.1.45**.
- compose (`router/docker-compose.yaml`): `ulimits.memlock: -1` (page-locked
  эксперты 47/36 ГиБ; без этого движок падает на mlock); RO-маунты
  `/opt/strata/{models,packs,mtp,data}` по абсолютным путям конфигов; лаунчер
  и контейнерные конфиги — `./strata:/app/strata:ro` (правка без пересборки);
  `extra_hosts` прежнему shim-пути не нужен и снят.
- Контейнерные конфиги `router/strata/*.container.json` — копии нативных с
  единственной готовкой `host: 0.0.0.0`; всё остальное (args, expert-cache,
  vision `gpu: false`, draft_vocab) — бит в бит с нативными.
- **`cmd` исполняется llama-swap без shell** (shlex-сплит,
  `exec.CommandContext(args[0])`), поэтому RAM-гейт — в скрипте-лаунчере
  `router/strata/strata-launch.sh <need_KiB> <config> <port>`: нехватка
  `MemAvailable` → мгновенный отказ с причиной; проход → `exec server.py` —
  движок становится тем же PID, что трекает llama-swap (SIGTERM = graceful
  QUIT по пути server.py #96).

### 2. Конфиг-схема: профили только для движка родителя

`router/config.yaml` — профили **только** `llama`/`ninfer`, каждый с
единственным пином `qwen3.8-27b → backend-*`; все пины `~` и страта-профили
удалены. Strata-ID (`config.d/30-strata.yaml`) — реальные `cmd`-модели
(`proxy: http://127.0.0.1:${PORT}`, `checkEndpoint: /health`) и нигде не
запинены, поэтому:

- `/v1/models` всегда показывает три рабочих ID — 404-ловушек пин-схемы нет;
- все модели без явного `routing:` живут в одной дефолтной exclusive-группе
  v265 — запрос к любому ID запускает swap: стартуется целевой процесс после
  выхода вытесненных (`doSwap`, `router/base.go:243`: останов → `wg.Wait()` →
  старт). Порядок unload→start, на котором держалась вся RAM/VRAM-безопасность
  strata-use.sh, теперь даёт сама группа;
- UI llama-swap становится полноценным: три ID в листинге, Play стартует
  движок, PowerOff = SIGTERM (graceful останов).
- Выбор llama.cpp ↔ NInfer для `qwen3.8-27b` — по-прежнему `PUT
  /api/profiles/active` или пикер UI, но теперь это **предпочтение
  производительности**, не условие работоспособности: любой из трёх ID
  отвечает при любом активном профиле. Дефолт — `ninfer`.

Полностью плоская схема (без профилей) отклонена: у v265 одна модель = один
`cmd`, а `groups`/`matrix` не выражают «один ID → два движка».

### 3. Политика отказов: fail fast + RAM-гейт, без ретраев

- RAM-гейт в лаунчере наследует пороги strata-use.sh: **46 ГиБ** (iq3) /
  **36 ГиБ** (iq2) `MemAvailable` — page-locked эксперты 47/36 ГиБ + запас.
  Гейт выполняется уже после выгрузки вытесненного бэкенда (п. 2), поэтому
  видит реальные остатки RAM.
- Любой провал старта/health-check — быстрая ошибка запроса (обычно
  `500 upstream command exited prematurely`) с точной причиной в логах
  контейнера; авторетраев нет — клиент видит ошибку и решает сам.
- VRAM-красные линии обеспечивают профили движков (`kv-capacity auto`,
  headroom, `--vram-reserve-mib` в конфигах Strata) — как и раньше; автомат
  их не меняет.

Верифицировано тикетом 11: фунд 20 ГиБ на хосте (MemAvailable 34.6 ГиБ <
порогов) → оба strata-ID дают `500` за 0.27–2.15 с с причиной
(`strata: RAM gate: need 46GiB, MemAvailable 35912MiB`) в логах; восстановление
обычным запросом.

### 4. Демонтаж нативного lifecycle — полный, сразу

Снесено внедрением (тикет 10) и не подлежит восстановлению как «аварийный
путь»: `scripts/strata/` целиком (strata-use.sh, strata-stop, strata.service,
README), симлинки юнита и `/usr/local/sbin/strata-stop`, симлинк
`/etc/strata/active.json`. Аварийные операции — обычные контейнерные
(`docker compose restart / up -d --force-recreate`, UI, `PUT /api/profiles/active`,
`docker logs`/`docker exec llama-swap`); ранбук — `docs/runbook-strata.md`.

Нативная установка `/opt/strata` на хосте сохранена нетронутой (движок 0.1.44,
нативные конфиги `172.17.0.1`, venv) — база отката: коммит до внедрения
(`7cc3ac8`) + старый образ `llm-server/router:v265`.

### 5. Что наследуется у ADR-0007 без изменений

- Три публичных ID и их обоснование (пересмотр ADR-0006 «один ID»).
- Контракт strata-ID: reasoning-словарь движка `none|low|medium|high`
  (`xhigh` принимается, но неотличим от `high` — не даётся), невалидное
  значение → `400`; tool calls работают, structured output + tools → `400`;
  поле `model` в ответе — канон native-ID
  (`qwen3.8-flash-next-iq3_xxs`/`…-iq2_xs`), llama-swap его не переписывает —
  не сверять с запрошенным; `repetition_penalty` стрипается.
- RAM-физика последовательного доступа (59 ГиБ; эксперты 43/35.5 ГиБ;
  page-locked родителей 47/36 ГиБ) и красная линия GPU1 ≥ 512 MiB.
- Роли размеров и первоисточник замеров — `docs/research/0016` (и 0016 §6 —
  риски движка).
- Клиенты (opencode, bench.py) не тронуты; окна молчания холодного старта —
  `docs/runbook-strata.md`.

## Отвергнутые альтернативы

- **Нативный Strata + host-агент за shim-cmd** (вариант 08-б): сохраняет весь
  демонтаж-объём (юнит, симлинки), добавляет ещё один нестандартный узел
  (агента) в цепочку «запрос → движок»; контейнерный путь проще и устраняет
  сам класс отказов «shim жив, движок хоста нет».
- **Отдельный контейнер Strata через docker.sock-шим**: llama-swap не умеет
  делать docker-операции — снова внешний оркестратор, то, от чего уходим;
  docker.sock (запрет ADR-0006) не монтируется.
- **Полная плоская схема без профилей**: нереализуема на v265 для «один ID →
  два движка» (см. п. 2).
- **Ретраи llama-swap при провале старта**: маскируют нехватку RAM; решение
  — честный быстрый отказ (п. 3).
- **Idle-политика** (возврат на «домашний» движок): отложена (map.md
  «Not yet specified») — нет механизма и не доказана нужда.

## Последствия

- Любой из трёх ID отвечает по запросу на `:8080` без ручных шагов; после
  ребута хоста контейнер поднимается сам (`restart: unless-stopped`), активен
  дефолтный `ninfer` с прелоадом; автостарты Strata платят обычные запросы
  (ребут-тест 11/11, `assets/11-reboot-test.md`).
- Верификацией (тик 11) подтверждено: холодные загрузки iq3 17.8–20.9 с /
  iq2 12.7–13.8 с (профильные нормы прежние), qwen-cold 7.4–8.9 с; GPU1 min
  710 MiB; листинг три ID в любом состоянии; конкурентность — FIFO-сериализация
  смен, co-residency тяжёлых бэкендов не выявлена; decode 0.1.45 в допусках
  0016 (iq3 131–133, iq2 129–138 tok/s), admission 71–79 %.
- **Движок в контейнере 0.1.45 против нативного 0.1.44** — по правилу AGENTS
  это новая точка калибровки: сменился только контейнерный движок; наблюдать
  деградации (CJK, thinking-обрывы, `#1944`-тип) на живых сессиях.
- Логи: stdout контейнера (`docker logs llama-swap` — server.py и decode/
  admission-строки движка) + движок-лог внутри контейнера
  (`docker exec llama-swap cat /opt/strata/strata-iq3_xxs.log`, аналог для
  iq2). `journalctl -u strata` больше не существует.
- Изменение `router/config*.yaml` — перезапуск llama-swap (нюанс
  single-file-маунта `router/config.yaml` и `up -d --force-recreate` — как в
  ADR-0006); изменение `router/strata/*` (лаунчер, контейнерные конфиги) —
  RO-маунт, достаточно `restart`. Пересборка образа — при смене пинов
  движков или исходников Strata (`docker compose build llama-swap`).
- Метрики llm-monitoring остаются вне топологии.

Опора: карта `.scratch/strata-integration/` (map.md, решения тикетов 07–09,
исполнение 10, верификация 11, сырьё `assets/09-config-draft.yaml`,
`assets/11-*`), research `0016` (размеры), `0011–0013` (контракты), код v265
в `../llama-swap` (doSwap, дефолтная группа, exec без shell).
