# ADR-0007: Strata (Qwen3.8-Flash-Next) за llama-swap — три публичных ID и последовательный доступ

Status: superseded в механике подключения и переключения — **ADR-0008**
(автоматический swap, движок в роутер-контейнере, демонтаж `strata-use.sh` и
`strata.service`); 2026-10-19. Разделы о трёх публичных ID, RAM-физике и
контракте strata-ID остаются действующими и унаследованы ADR-0008 (п. 5).
Ниже — текст в состоянии accepted (2026-10-19), сохранён как первоисточник
первой итерации; механика пинов `~`, shim-моделей, нативного юнита
`strata.service` и оркестратора `strata-use.sh` больше не существует.

## Контекст

Отчёт `docs/research/0016-strata-flash-next-selection.md` (матрица замеров
2026-10-18) выбрал для постоянной эксплуатации нативный движок Strata
(`/opt/strata`, CUDA 13.3, 0.1.44-линейка) с двумя размерами:

- **IQ3_XXS @131072** — основная роль (сложные вопросы, планы, постановка
  задач субагентам): лучшее публикуемое качество, доступное этому железу
  (84.46 % top-token), decode 129–153 tok/s;
- **IQ2_XS @262144** — вторая роль (повседневные задачи с большим окном):
  лучший decode тройки (144.9/154.7 tok/s), целиком в RAM, лучшая VRAM-гигиена.

IQ3_S — runner-up, в схему не входит (конфиг `/opt/strata/strata-iq3_s.json`
на хосте есть, возвращается отдельным тикетом при починке апстрим-блокера
`--resident-experts`).

Физика RAM не допускает резидентности двух размеров одновременно: экспертам
нужно 43 GB (IQ3_XXS) + 35.5 GB (IQ2_XS) при 59 ГиБ доступной RAM; не
уживаются они и с llama.cpp, держащим до ~40 ГиБ `--cache-ram`. Доступ —
**последовательный**: ровно один бэкенд резидентен в любой момент.

При этом ADR-0006 зафиксировал «ровно один публичный ID» (`qwen3.8-27b`) и
запуск всех движков llama-swap как дочерних процессов. Strata нативна на
хосте: llama-swap не может запустить её как `cmd` (процесс вне контейнера),
hooks команд не умеют, unix-socket ни у одной из сторон нет.

## Решение

### 1. Три публичных ID (пересмотр ADR-0006, п. 2)

Публичный контракт `http://localhost:8080` — **три** model-ID:

| ID | Размер / контекст | Движок |
|---|---|---|
| `qwen3.8-27b` | 262144 | llama.cpp или NInfer по активному профилю (как в ADR-0006) |
| `strata-iq3` | 131072 | нативная Strata, конфиг `strata-iq3_xxs.json` |
| `strata-iq2` | 262144 | нативная Strata, конфиг `strata-iq2_xs.json` |

Шим-модели объявлены прямо публичными ID (промежуточные имена ничего не
добавляют, а пины профилей ссылаются на реальные имена моделей) в
`router/config.d/30-strata.yaml` — видимые, не `unlisted`. Профильная
дисциплина пинов `~`:

- профили `strata-iq3`/`strata-iq2` закрывают родителя `qwen3.8-27b`,
  `backend-llama`/`backend-ninfer` и **соседний размер**;
- родительские профили `llama`/`ninfer` закрывают оба strata-ID.

Это осознанный пересмотр «ровно один ID»: незакрытый strata-ID под
родительским профилем стартовал бы shim по случайному запросу, выгнал бы
родительский движок (дефолтная exclusive-группа) и завис на мёртвом upstream;
пин `~` даёт быстрый чистый `404`.

### 2. Shim-модель как механика подключения

llama-swap v265 умеет только дочерние процессы (`cmd` обязателен — иначе
`prematureExit`), поэтому процесс-носитель — watchdog-пустышка, а трафик
уходит через `proxy` на уже работающий нативный сервер:

- `cmd: sh -c 'while curl -sfm 2 http://host.docker.internal:8081/health …; do sleep 1; done'` —
  shim живёт, только пока нативный `/health` отвечает;
- `proxy: http://host.docker.internal:8081`, `checkEndpoint: /health`;
- сеть: Strata привязана к `172.17.0.1` (docker0), контейнер достаёт её через
  `extra_hosts: host.docker.internal:host-gateway`; при не-loopback привязке
  Strata сама допускает имя `host.docker.internal`; с LAN сервер не виден.

Fast-fail обязателен из-за бага v265: пер-модельный `healthCheckTimeout` не
работает (`config/load.go:136` перезаписывает его глобальным — 600 c,
максимум родительских холодных загрузок). При остановленном юните watchdog
выходит за ~2 c → `prematureExit` → ошибка запроса сразу, без 600-секундного
зависания (замеры: 0.56 c юнит выключен, 0.26 c юнит умер под живым shim).

### 3. Последовательный доступ: `strata-use.sh` — единственная точка правды

Переключение ролей — только `scripts/strata/strata-use.sh
{llama|ninfer|strata-iq3|strata-iq2|off}` (коды выхода 0–7, идемпотентен).
llama-swap не владеет нативным движком и не претендует: пины не производят
ни start, ни stop движка. Обязательный порядок перехода на Strata:

1. останов юнита, если работал (`systemctl stop` + ExecStop-добивание дерева,
   ожидание ухода процессов и VRAM);
2. `POST /api/models/unload` — убивает родительский процесс llama-swap:
   page-locked RAM (47/36 ГиБ под IQ3_XXS/IQ2_XS-профиль) уходит за секунды;
   при резидентном родителе старт Strata = OOM VRAM (замерено: arena
   cudaMalloc при 869 MiB свободных);
3. RAM-гейт: available ≥ **46 ГиБ** (iq3) / **36 ГиБ** (iq2), иначе отказ
   (exit 5) — защита от не освободившегося idle-cache llama.cpp;
4. симлинк `/etc/strata/active.json` → конфиг размера, `systemctl start strata`;
5. ожидание `/health` на `:8081` с **дискриминатором рассинхрона** — payload
   `model` == native-ID конфига (`qwen3.8-flash-next-iq3_xxs` / `-iq2_xs`) и
   `loaded: true` (сам `/health` отвечает 200 при любом размере; готовность
   iq3 ~20–24 c, iq2 ~14 c);
6. только после совпадения — `PUT /api/profiles/active` на strata-профиль.

Переход на родителя: останов юнита (+ VRAM-проверка) → `PUT` профиля; движок
родителя стартует на первом запросе. `off` — юнит down + дефолт-профиль
`ninfer` (как в `hooks.on_startup`).

Юнит `strata.service` (`scripts/strata/`, установлен симлинками): **linked,
НЕ enabled** (после ребута VRAM не захватывается в обход родительского
профиля), `Restart=no`, `ExecStartPre` отказывается без симлинка
`/etc/strata/active.json` (вручную юнит без него не запустить). `ExecStop`
(`scripts/strata/strata-stop`) добивает дерево: TERM всему дереву
(server.py, engine/strata, strata-vision) → ждать ≤ 10 c → KILL; подстраховка
systemd `KillMode=control-group` + `TimeoutStopSec=25` — SIGTERM server.py
однажды был проглочен, а движок-ребёнок держал VRAM/RAM до прямого kill.

Единственный формат запуска движка: `python serve/server.py --engine strata
--config <json> --port 8081` — HTTP-порт берётся **только из CLI** (дефолт
8095, `--port 8081` в юните обязателен), host — **только из конфига**
(172.17.0.1).

### 4. RAM/VRAM-рамки

- RAM хоста 59 ГиБ; page-locked экспертов под резидентной Strata —
  47 ГиБ (IQ3_XXS, available 11.7–13.6 ГиБ) / 36 ГиБ (IQ2_XS, ~19 ГиБ);
- RAM-гейты скрипта перед стартом — 46/36 ГиБ available (см. п. 3);
- красная линия проекта — **≥ 512 MiB свободной VRAM на дисплейной GPU1**;
  под живой Strata свободно 1671–1707 MiB, минимум верификационного цикла —
  709 MiB (при резидентном ninfer) — линия не тронута;
- co-residency двух размеров невозможна (п. «Контекст»), свап размеров —
  полная перезагрузка весов (десятки секунд + давление на page cache).

### 5. Контракт запросов на strata-ID

- Reasoning — словарь движка **`none|low|medium|high`** (top-level
  `reasoning_effort` или `chat_template_kwargs` — оба пути через `:8080`
  работают). `xhigh` движок принимает (200), но статистически неотличим от
  `high` — клиентам не предлагается. Невалидное значение → `400`
  («use none, low, medium or high»).
- Tool calls работают (forced tool choice → 200); **structured output +
  tools → `400`** («structured response_format with tools/MCP is not
  supported»).
- Strata отрабатывает любой `model` запроса, поэтому шимам `useModelName`
  не нужен, но поле `model` в **ответе** — канон native-ID
  (`qwen3.8-flash-next-iq3_xxs` / `…-iq2_xs`); llama-swap ответ не
  переписывает — клиентам не сверять `model` ответа с запрошенным ID.
- Семантика листинга v265: под strata-профилем `/v1/models` отдаёт **две**
  записи (родитель исчезает из листинга при пине `~` — мета-тип profile),
  тогда как запиненные strata-ID под родительскими профилями остаются в
  листинге (`status: unloaded`, запрос → `404`).
- Vision: mmproj BF16 квантован локально в Q8_0, энкодер `strata-vision`
  работает на CPU — GPU не занимает.

## Отвергнутые альтернативы

- **Один публичный ID со swap по запросу** (B1/peers, селекторы): нарушает
  последовательный доступ — RAM физика требует ручного порядка
  unload → юнит → health, который по запросу клиента не выразить; для
  честности «ID ↔ загруженный размер» всё равно нужен внешний оркестратор.
- **Запуск Strata через hooks / unix-socket**: hooks не умеют команд,
  unix-socket ни у одной из сторон нет (feasibility — 0016 §9).
- **Контейнерный cmd с честным swap** (план B 0016): третий образ-пин,
  memlock/unloadTimeout, весы в контейнере — сложнее и не даёт ничего
  против нативного юнита.
- **Прямые запросы к strata-ID без профиля-владельца**: отклонено — пины
  работают только над запрошенным именем и не производят ни start, ни stop;
  без страта-профилей нечем закрыть соседние бэкенды (п. 1).
- **Резидентность обоих размеров / Strata рядом с llama.cpp**: 43 + 35.5 GB
  экспертов > 59 ГиБ RAM — физически невозможно (модель co-residency не
  проходила даже на этапе selection).
- **Отдельный провайдер opencode на `:8081`** (вариант C 0016): дешёвый
  старт, но ломает единый endpoint и клиентский контракт; после интеграции
  потребители ходят только через `:8080`.

## Последствия

- `/v1/models` на `:8080` — три ID; переключение ролей — только
  `strata-use.sh` (аварийный ручной путь — `docs/runbook-strata.md`).
- opencode (`~/.config/opencode/opencode.jsonc`): strata-варианты — top-level
  `reasoning_effort` `off`→`none` / `low` / `medium` / `high`; `xhigh` для
  Strata не даётся (п. 5).
- Метрики Strata — `journalctl -u strata` (логи server.py) +
  `/opt/strata/strata-*.log` (файл-лог движка) и собственный мониторинг;
  llm-monitoring (promtail/Loki/Grafana) выключен и вне карты (его останов
  освободил `:8081`; при возврате — сначала увести его cadvisor с 8081).
- Риски движка (0016 §6, сообщество, у нас не воспроизведены, но относимы):
  CJK-коллапс на длинных выводах (#1827), агрессивный thinking — обрыв ответа
  внутри `</think>` без закрытия (задавать `max_tokens` с запасом ≥ 12–16K),
  деградации под RAM-пресурой. Каждая смена версии движка — новая точка
  калибровки и smoke-check кванта.
- Изменение `router/config.d/30-strata.yaml` и других `router/config*.yaml`
  требует перезапуска llama-swap; при правке `router/config.yaml` подменой
  файла (rename) restart не подхватывает новый инод — нужен
  `docker compose up -d --force-recreate llama-swap` (stale single-file
  mount; `config.d/` смонтирован директорией — там проблема невозможна).
