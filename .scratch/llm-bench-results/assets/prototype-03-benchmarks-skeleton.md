# Бенчмарки: три модели через :8080

Одноразовый прогон бенчмарк-набора [llm-bench](https://github.com/Grigory-Rylov/llm-bench)
(коммит `<pin>`, дата прогонов `<дата>`) для трёх публичных моделей роутера

## Протокол

- Промпты — реальный текст (Project Gutenberg), чанки взаимно непересекающиеся:
  ни один замер не обслуживается контекст-кэшем другого (проверяется по
  `cached_tokens`/`cache_n`).
- **Prefill** (`bench-real-prefill.sh`): 3 прогона на глубину (у каждого — свой
  чанк) + decode-пробник (~128 токенов, 3 прогона). Глубины:
  `qwen3.8-27b`/`strata-iq2` — 40k/150k/200k; `strata-iq3` — 40k/120k
  (контекст 131072).
- **Параллельный декод** (`bench-parallel-decode.py`): solo (2 прогона) против
  `--concurrency 2` (3 прогона), чанки 40k, разнесённые слоты против кэша.
- Engine tok/s — из `timings` движка (у всех трёх моделей в стриме есть);
  если у прогона `timings` не было — client-side значение помечается `*`.

## Варианты решения, по которым пользователь реагирует

1. **Схема таблиц**:
   - (a) строки = модель×глубина, три таблицы (prefill / decode / parallel) —
     как в черновике; 8+8+6 строк, всё на одном развороте;
   - (b) по таблице на глубину (40k/120k/150k/200k) — глубины сопоставимы
     построчно, но 4 таблицы и разное число моделей на глубину;
   - (c) модели — колонки, глубины — строки (компактно 3×3, но у iq3 глубины
     другие → рваная таблица с прочерками).
2. **Ссылка в README.md**:
   - (a) новая строка в списке секции «Схемы работы» (рядом с flowchart/
     sequence/states):

       prefill/decode бенч-набором llm-bench на реальном тексте (thinking off).`
   - (b) отдельная секция «Бенчмарки» (после «Схемы работы»).
