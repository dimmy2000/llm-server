## Answer

Grilling 18.10.2026; протокол утверждён пользователем (все решения — его). Исполняемый
протокол матрицы:

### 1. Калибровка

- Каждая модель: после установки, до её матрицы — `./setup.sh --calibrate`; она сама в
  конце запускает модель, вручную не стартовать. В сессии калибровку не прерывать.
- Замеряем **калиброванное** состояние каждой модели (постоянно жить будет именно оно;
  калибровка меняет routing/пайпинг, не качество квантизации, поэтому честно для сравнения
  размеров). Настройка калибра → лог.
- Дельта-микробенч до/после калибровки (chat + 16K) — один раз, на IQ3_XXS; для S и XS —
  сразу калиброванное.

### 2. Vision

- mmproj **Q8_0** на все три размера (шард общий, один раз); текстовая серия — без
  encoder-резерва, `elastic` не активен.
- После текстовых прогонов — один smoke-запрос с картинкой при **CPU-encoder**: если
  работает — это наш **стандарт использования**, замер относим к нему: корректность ответа,
  время обработки (ориентир ~3 с на 300 ток.), свободная RAM/VRAM в этот момент.
- CPU-encoder сломан или неприемлемо медленный → факт в лог + один повтор smoke на
  GPU-encoder (`elastic`) как отраслевой fallback с его VRAM-ценой; решение о переключении —
  вне матрицы.
- Паритет с NInfer по vision сохраняется; VRAM под encoder мы не платим.

### 3. Гэп-лист → живой тест opencode против `:8081`

Разово, один раз на модель:

1. Forced/named tool choice → ожидаем отказ; фиксируем как именно.
2. Structured outputs (`json_schema`) + tools → ожидаем отказ; как именно.
3. Невалидный `reasoning_effort` → ожидаем 400; фиксируем код/текст.
4. `xhigh` на chat-пути → работает или нет; если нет — variant `high`.

На каждой агент-сессии, совместно с основной:

5. Side-запрос во время основной сессии → строки `prompt N tokens = X reused + Y read`
   до/после (cold re-read, eviction warm-сессии); обход — `--conversation-cache-slots` —
   проверяется в этом же тесте.
- Prefix-cache чувствительность (#10) — наблюдаем по жилым строкам reused/read во всех
  сценариях, отдельной проверки нет.

**Параллелизм не является целью: слот один (`parallel: 1`, без `--batch`); при выборе
«слоты или контекст» — контекст. Batching не замеряем.**

### 4. Потолки контекста и нагрузки

Потолок задаётся при установке, подтверждается стартовой строкой движка («N MiB of VRAM
free with everything loaded»):

- IQ3_S — 64K; IQ3_XXS — 128K; IQ2_XS — старт с 128K, если свободная VRAM на каждой карте
  ≥ 1 GiB — поднимать до 262 144; фактический потолок фиксируется замером, не догадкой.

Нагрузки (на каждую модель, в этом порядке):

1. `bench.sh chat` (≤ 100 ток.) — decode tok/s, TTFT.
2. `bench.sh 16K` (fresh prompt) — prefill tok/s, TTFT.
3. `bench.sh --long` (32K) — prefill tok/s.
4. Потолочный пробой (кастомный openai-клиент): промпт ~90 % потолка + генерация до ~4K;
   3 повторения, медиана; минимум VRAM GPU1 за ход, decode при полном KV.
5. Agent-session × 2: (а) `bench.sh agent-session` (5 туров) — reused/re-read, TTFT
   по турам; (б) живая opencode-сессия, фиксированный таск с tool calls + гэп-чек-лист +
   side-запрос; субъективная оценка.
6. Длинный многотуровый чат (кастомный клиент): 12–15 туров до красной линии RAM или
   потолка контекста; своп-in/out, VRAM GPU1, reused-строки по ходу.
7. Soak: 3 подряд холодных старта модели + полный цикл переключений
   XXS→S→XS→стоп; RAM/VRAM после останова возвращаются к исходным.

Ориентир времени ~1–1.5 ч на модель; прогон многосессионный (окна остановленного стека).

### 5. Артефакты (`.scratch/strata-model-selection/assets/`)

```
assets/
  status.md                       ← статус-борд: модель → состояние сценариев (done/pending/blocked)
  summary-matrix.md               ← сводный документ, собирается по окончании (вход тикета «Отчет и решение»)
  <model>-<size>/
    calibrate.log + settings      ← калибровка + подобранные настройки
    bench/<scenario>/             ← родные папки bench.sh (--out сюда)
    custom-*.json                 ← кастомные прогоны (потолок, много-turn чат, soak)
    engine-log-slice.log          ← вырезки лога движка за серию
    watch.log                     ← монитор per-model, интервал 2 с
    cover.json                    ← паспорт прогона: дата, версия движка, драйвер, контекст,
                                    сценарий → статус/медианы; статус многосессионности
    watch-аннотации.md            ← минимумы GPU1/GPU0/RAM, максимум свопа/диска за серию
```

Числа (единый набор на все сценарии): decode tok/s, TTFT, prefill tok/s, reused/read
per-запрос, минимум свободной VRAM GPU1 и GPU0, минимум свободной RAM, максимум swap,
page-lock-warning («only N of M GiB could be page-locked»), максимум read NVMe, старт→готовность,
pass/fail сценария; на XXS — дельта калибровки.

### 6. Чек-лист стабильности (порог на каждый сценарий)

- **VRAM GPU1**: минимум за сценарий ≥ 512 MiB; ниже → `red-line-breach`.
- **RAM/swap**: swap-in во время decode или рост использованного свопа > 2 GiB за сценарий → `ram-pressure`.
- **Диск**: чтение NVMe > 200 MB/s дольше 20 с вне prefill-фазы → `disk-storm`.
- **Зависание**: нет прогресса токенов > 120 с в decode (TTFT-фаза до 5 мин легальна на
  потолочном пробое) → `hang`; живость контролируем и по keep-alive-строкам движка (15 с).
- OOM/зависание/шторм/постоянный своп — жёсткие провалы; decode > 20 tok/s — ещё и
  скоростной критерий.

Политика при сбое: один ретран (чистый рестарт движка + один повтор сценария); повторный —
окончательный fail. Краш движка: рестарт модели, сценарий с начала; `OOM at load` дважды →
модель не годится, ранний стоп. Сценарий можно перенести в следующую сессию (статусы в
`status.md`/`cover.json` — без перезамера, кроме случаев, когда сбой был в самой модели).
Сбой, атрибутированный окружению (фон, браузер), — `environment-retry` с аннотацией.

### 7. Порядок моделей и ранний стоп

- Порядок: **IQ3_XXS → IQ3_S → IQ2_XS**, каждая в своей сессии (стек вниз, Strata на
  `:8081`, обе карты; fallback одной карты — если VRAM GPU1 рушит красную линию).
- **RAM-сбой XXS → пропуск S, сразу XS** (S наследует ту же механику с ареной на 7 GB
  больше). Пропуск фиксируется явно («пропущена по правилу раннего стопа», не «не замерена»).
- **Нерam-сбой XXS/S → порядок сохраняется**: следующая по списку всё равно меряется
  (KV/весовой профиль отличаются).
- Идеально прошедший XXS не останавливает матрицу: решение требует сравнения размеров.
- Все три провалились — легальный исход «никакой не подходит» и вход в fog-вопрос
  «что дальше» (карта, Not yet specified).
