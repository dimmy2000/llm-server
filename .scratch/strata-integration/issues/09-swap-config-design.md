# Дизайн конфига llama-swap: три ID без 404-ловушек

Status: resolved
Type: grilling
Blocked by: 08

## Question

(HITL, гриллинг; при необходимости черновик конфига как дешёвый артефакт для
реакции) Спроектировать конфигурацию llama-swap, в которой все три публичных ID
(`qwen3.8-27b`, `strata-iq3`, `strata-iq2`) сосуществуют и переключаются
автоматически по запросам. Уроки первой итерации обязательны к устранению:

- **Профили/группы/пины:** пин-семантика v265 создавала 404-ловушки
  (`no model id could be identified` при рассинхроне «активный профиль ↔ ID»;
  `status: unloaded` у пин-записей — косметика). Нужна схема, где `/v1/models`
  всегда честно показывает три рабочих ID и ни один запрос не падает из-за пина.
  Вопрос: одна плоская схема с exclusive-группами вместо ручных профилей
  (`llama`/`ninfer`/`strata-*`) целиком, или профили сохраняются только для
  выбора движка родителя?
- **Движок родителя:** при запросе `qwen3.8-27b` кто решает llama.cpp vs NInfer —
  профиль (остаётся ручным?) или тоже автоматика? Это решение прямо влияет на
  дестинацию «ноль ручных шагов».
- **on_startup:** что прелоадить при старте роутера (сейчас NInfer ~6 c); стоит
  ли вообще что-то, при чистом on-demand.
- **Молчание холодного старта и таймауты клиентов:** llama.cpp молчит 40–60 c,
  Strata ~15–25 c; `sendLoadingState: false` стримит баннер только в
  `delta.reasoning_content`. Какие таймауты/настройки нужны клиентам (opencode,
  bench.py), чтобы переживать холодный старт — и где это фиксируется.

Resolved when: схема конфига согласована (черновик YAML приложен как артефакт),
тикет закрыт, указатель в Decisions so far; спецификация передана тикету 10.

## Answer

(Гриллинг 2026-10-19, HITL; факты проверены по коду v265 в `../llama-swap`.
Черновик конфига — `assets/09-config-draft.yaml`.)

1. **Схема — профили только для движка родителя, strata-ID нигде не запинены.**
   - Профили `llama`/`ninfer` содержат по одному пину
     `qwen3.8-27b → backend-llama|backend-ninfer`; страта-профили и все пины
     `~` удаляются. Полностью плоская схема невозможна без нарушения
     контракта: у v265 одна модель = один `cmd`, а механики `groups`/`matrix`
     маршрутизируют по модельным ID и не выражают «один ID → два движка».
   - Основание: пины применяются только к заявленным ID
     (`internal/server/profiles.go:25` — незапиненные проходят пайплайн
     как обычные модели); все модели без явного `routing:` попадают в одну
     дефолтную exclusive-группу (`config.go: AddDefaultGroupToConfig`,
     swap+exclusive). Явный `routing:`-блок не нужен.
   - Порядок unload→start подтверждён по коду: `doSwap`
     (`router/base.go:243`) останавливает вытесняемые процессы и ждёт
     их выхода (`wg.Wait()`) до старта целевого `cmd` — RAM-гейт страты
     видит уже освобождённый page-лок родителя.
2. **Движок родителя — выбор llama.cpp vs NInfer остаётся ручным**
   (`PUT /api/profiles/active` / пикер UI), но меняет статус: это
   предпочтение производительности, а не условие работоспособности —
   любой из трёх ID отвечает при любом активном профиле. Дефолт — ninfer.
3. **UI (факт, вскрывшийся при обсуждении):** нынешние ограничения
   («видны только strata, старт/стоп невозможны, родителя нет в списке») —
   следствие пин-схемы и шимов, не поломка UI: записи с пином `~`
   пропускаются в `/v1/models` (`api.go: target == ""`), Play дёргает
   `/upstream/<model>/` → 404 у запиненных, шим умирает за ~2 c. Новая
   схема чинит всё структурно: strata всегда видны и управляемы из UI
   (Play = старт движка, PowerOff = SIGTERM), `qwen3.8-27b` всегда в
   листинге (пин непустой). Живая проверка пикера профилей и старт/стопа
   через UI — обязательный пункт верификации (тик 11).
4. **on_startup — без изменений:** профиль `ninfer` + прелоад
   `backend-ninfer` (~6 c). Стартовый `[ERROR] failed to preload
   backend-ninfer: status 404` — известная косметика.
5. **Таймауты и молчание — без изменений:** `sendLoadingState: false`
   (issues/13, ADR-0006), `healthCheckTimeout: 600` (глобальный; per-model
   в v265 не работает). Fail fast обеспечивают RAM-гейт в `cmd` и
   prematureExit; ретраев нет. Клиенты (opencode, bench.py) не правятся;
   окна молчания (NInfer ~6 c, Strata ~15–25 c, llama.cpp 40–60 c)
   фиксируются в runbook (тик 10) и проверяются пилотом (тик 13).
6. **Стиль конфигов:** комментарии — минимальные и стабильные
   (однострочные, с указателями на ADR/runbook/research); нюансы и история
   — только в документации проекта, не в конфигах.

Спецификация передана тику 10 (п. 2 дополнен ссылкой на черновик и
заметками к реализации: memlock ulimit=-1, маунты RO весов, контейнерные
конфиги `host: 0.0.0.0`, демонтаж-лист, `extra_hosts`).
