> самих тикетах с пометками superseded; ещё-валидные факты впитаны в Notes ниже.

## Destination

Все три публичных ID (`qwen3.8-27b`, `strata-iq3`, `strata-iq2`) всегда доступны на
`:8080`, и **любой запрос к любому из них сам приводит систему в нужное состояние**:
поднимает Strata, вытесняет её обратно на родителя, переключает `iq3`↔`iq2` —
ровно так, как llama-swap управляет `qwen3.8-27b`. Ручных шагов нет: ни
`strata-use.sh`, ни `PUT /api/profiles/active`, ни sudo. Контракт клиентов
(opencode, потребители) не меняется — выбор ID в клиенте и есть переключение.
Дестинация — работающий автомат, верифицированный и задокументированный.

## Notes

- Решения стартовой фазы переработки (гриллинг 2026-10-19, подтверждены пользователем):
  - **Полный автомат** — любой запрос к любому из трёх ID работает без ручных шагов;
    strata-use.sh как обязательный путь исчезает.
  - **Механика автостарта — решить после research**: llama-swap управляет только
    процессами внутри своего контейнера, Strata сейчас нативная на хосте. Основной
    кандидат — контейнеризация Strata (обычный cmd-бэкенд, exclusive-группа llama-swap
    сама даёт безопасный порядок unload→start); нативность была «режимом эксперимента»
    (0016), не железным требованием; в `/opt/strata` есть upstream `Dockerfile` и
    `docker-entrypoint.sh`. Решение — тикет после research-тика.
  - **Чистый on-demand** — каждая смена роли платит холодную загрузку молча
    (llama.cpp 40–60 c, Strata ~15–25 c, NInfer ~6 c); idle-политик нет (см. туман).
  - **Переработка на месте** — эта карта и каталог тикетов продолжаются; история
    первой итерации — в архивных тикетах 01–06.
- **Исполняющее усилие:** task-тикиеты меняют конфиги и код прямо на карте — пункт
  назначения это артефакт «инфраструктура обновлена и работает», не отдельная спецификация.
- Железо/стек: 2× RTX 5070 Ti (16 GB, GPU1 дисплейная, красная линия ≥ 512 MiB),
  59 GiB RAM, драйвер 615.71.09-p2p. Родительский стек: llama-swap v265 на `:8080`
  (`AGENTS.md` в корне). Strata — сборка 0.1.44-линейки на CUDA 13.3 в `/opt/strata`.
- **RAM-физика (действует):** page-locked родителей 47 (llama.cpp) / 36 (NInfer) ГиБ;
  эксперты Strata 43 (iq3) / 35.5 (iq2) ГиБ. Два тяжёлых бэкенда никогда не резидентны
  вместе; порядок unload→start критичен (иначе OOM VRAM/RAM). Exclusive-группа
  llama-swap — предпочтительный механизм этого порядка.
- **Холодные загрузки (измерено первой итерацией):** llama.cpp 40–60 c, NInfer ~6 c,
  Strata iq3 ~20–24 c / iq2 ~14 c; тайминги в контейнере перепроверить (тикет верификации).
- **Контракт клиентов (действует):** opencode v2 уже настроен на три ID
  (`~/.config/opencode/opencode.jsonc`); reasoning-варианты: родитель —
  `off/low/medium/xhigh` (`chat_template_kwargs`/`reasoning_effort`), strata —
  top-level `reasoning_effort` `off→none/low/medium/high` (словарь движка; `xhigh`
  неотличим от `high` — не даётся). Env-нюанс запуска opencode: `env -u http_proxy
  -u https_proxy`. Цель автомата — клиентский контракт не трогать вообще.
- **Уроки первой итерации (учитывать в дизайне):** пин-семантика v265 создавала
  404-ловушки (`no model id could be identified` при рассинхроне «профиль ↔ ID»);
  per-model `healthCheckTimeout` в v265 не работает (config/load.go:136); watchdog-шимы
  и ручные профили — источник отказов, который новый дизайн конфига обязан устранить.
- Страта-запуск сегодня: `python serve/server.py --engine strata --config <json>
  --port <N>` (порт только в CLI, host — в конфиге); upstream-репо несёт `Dockerfile`
  и `docker-entrypoint.sh` — феасибилити контейнеризации проверяет research-тикет.
- llm-monitoring (promtail/Loki/Grafana) выключен и вне карты; его останов освободил `:8081`.
- Замеры и решение о размерах — `docs/research/0016-strata-flash-next-selection.md`;
  метрику не перепроверяем (санити-decode после интеграции — да, полный re-run нет).
- Язык сессий и отчета — русский. Навыки: `/grilling` для развилок, `/research` для
  research-тикетов; внешние репо `../llama-swap` (код v265) и `../llama.cpp`.
- Артефакты (raw-логи) класть в `.scratch/strata-integration/assets/`; изменения
  конфигов/доков — в git (ADR — в `docs/adr/`).

## Decisions so far

- [Research: феасибилити контейнеризации Strata и механики автостарта](issues/07-research-containerization.md) —
  контейнеризация феасибилити высокая (upstream Dockerfile/entrypoint, `CONFIG=`,
  `STRATA_EXECV`, веса маунтами RO; конфигу нужен контейнерный `host: 0.0.0.0`);
  апстрим llama-swap после v265 пуст, но в v265 найден per-model `cmdStop`;
  на выбор в тикете 08 — три варианта: движок в роутер-контейнере (как qwen),
  отдельный контейнер через docker.sock-шим, натив + host-агент.
- [Выбор механики автостарта и политики отказов](issues/08-mechanics-decision.md) —
  механика: **движок Strata в роутер-контейнере, «ровно как qwen»** (без
  docker.sock; exclusive-группа даёт порядок unload→start; upstream-сборка в
  образе, `memlock ulimit=-1`, контейнерные конфиги `host: 0.0.0.0`, веса RO);
  отказы: **fail fast + RAM-гейт в cmd** (46/36 ГиБ до запуска, без ретраев);
  старый lifecycle — **полный демонтаж сразу** (strata-use.sh, strata.service,
  strata-stop, watchdog-шимы, active.json; аварийный путь — контейнерные
  операции, runbook переписать). Демонтаж-лист → тик 10, схема конфига → тик 09.
- [Дизайн конфига llama-swap: три ID без 404-ловушек](issues/09-swap-config-design.md) —
  схема: **профили только для движка родителя** (по одному пину
  `qwen3.8-27b → backend-*`), strata-ID нигде не запинены и переключаются
  автоматически дефолтной exclusive-группой (порядок unload→start подтверждён
  по коду v265: doSwap ждёт выхода вытесненных до старта нового); выбор
  llama.cpp vs NInfer — ручной (PUT/пикер UI), но теперь это предпочтение,
  а не условие работоспособности; on_startup и таймауты — без изменений;
  UI-старт/стоп strata становится реальным. Черновик YAML —
  `assets/09-config-draft.yaml`; спецификация передана тику 10.

- [Верификационный проход автомата](issues/11-verification-auto.md) —
  resolved 2026-10-20: 4 цикла свапов по HTTP без ручных шагов (cold: iq3
  17.8–20.9 c, iq2 12.7–13.8 c, qwen-cold ~7.4–8.9 c, резидент 0.05 с);
  листинг три ID в любом состоянии; GPU1 min 710 MiB; RAM-гейты — быстрый
  500 с причиной, ретраев нет; конкурентность — FIFO-сериализация, отказов
  нет; decode 0.1.45 в допусках 0016 (iq3 131–133, iq2 129–138 tok/s);
  ребут-тест 11/11 — контейнер сам поднимается, автостарты работают по
  обычным запросам. Сырьё — assets/11-*.

## Not yet specified

- **Idle-политика (возврат на «домашний» движок после простоя).** Принят чистый
  on-demand; если пилот покажет, что переключения слишком частые/дорогие (холодные
  загрузки 15–60 с), вернуться к вопросу отдельным тикетом — сейчас механизм idle
  некому реализовывать и не доказана нужда.
- **Эргономика ошибок автомата для клиента.** Как именно запрос к недоподнимаемому
  бэкенду (нехватка RAM/VRAM, OOM, падение старта) выглядит для opencode — станет
  специфицируемо после выбора механики и дизайна конфига; может остаться частью
  тикета внедрения, а не отдельным тикетом.
