# Цикл свапов по HTTP-запросам (тикет 11, 2026-10-20)

Автоматическое переключение ролей без единой ручной команды: переход платит
сам запрос (первый запрос после смены ID несёт холодную загрузку бэкенда).
Сырьё: `11-cycle1.logjsonl` (первый прогон, дефект логгера харнесса — тайминги
верны, привязка меток шагов к временной оси сдвинута, движко-логи контейнера
подтверждают), `11-cycle-verify.logjsonl` (контрольный проход, чистый),
`11-monitor.log` (2-секундный сэмплер VRAM/RAM), логи контейнера llama-swap.

## Сводная таблица переходов (wall переходящего запроса, HTTP 200)

| переход (запрос платит) | прогон 1 | прогон 2 | контрольный | норма (0616/первая итерация) |
|---|---|---|---|---|
| qwen (resident) | — | — | 0.05–0.08 c | instant |
| qwen/NInfer → strata-iq3 (cold) | 20.86 | 17.81 | 17.79 и 26.95¹ | native 20–24 c; v0.1.44 было 29 c |
| strata-iq3 → strata-iq2 (cold) | 13.67 | 13.16 | 12.76 / 13.13 / 13.78 | iq2 ~14 c |
| parent → qwen/NInfer (cold engine) | 7.99 | 7.96–7.98 | 7.97 / 7.42 / 8.86 | engine ready total 7.2 s, ~6 c |
| qwen llama.cpp нога (PUT-профиль) | 11.6 | — | — | 40–60 c на холодном диске² |
| ninfer возврат (после llama) | 6.95 | — | — | ~6 c |

¹ единичный разброс — по данным сессии после RAM-прессы (испытание гейтов
вытеснило page cache); остальные замеры 12.8–21 s. Полоса контейнера =
13–27 c — так же, как нативная 14–29 c.
² замер с тёплым page cache (17,6 ГБ GGUF в кэше); историческая норма —
на холодном диске, не воспроизводится в этом тесте (кэш не чищен).

Движко-логи (контейнер): strata «experts loaded 39.97 GiB at 6.3–6.5 GiB/s
(14–15 s so far)»; NInfer «engine ready total 7.2 s». Прогревы движков
подтверждают долю wall: холодный старт из HTTP-ответа == старт движка +
health-check + сам ответ.

## Поведение хвостовых запросов

- Резидентность переживает запросы: повторный qwen-запрос на резидентном
  движке — 0.05 c (v4/v7/v12 контрольного прохода), «перезапуск на каждый
  запрос» не наблюдается.
- Возврат из strata на qwen всегда платит холодный старт NInfer ~7–9 c
  (бэкенд был выгружен при уходе на strata) — по схеме 09 это и есть
  on-demand-политика: перекат с размера на размер дёшев (безостановочно
  через RAM), в родителя — с холодной загрузкой весов 20,3 ГБ.

## Ответы и контракты

- все шаги HTTP 200; содержимое ответов корректно; при переключении
  бэкендов ни один запрос не разорвался.
- `model` в ответах strata-шим — канон native-ID
  (`qwen3.8-flash-next-iq3_xxs` / `…-iq2_xs`), в ответах родителя —
  `qwen3.8-27b` (llama.cpp-нога отдаёт путь GGUF — косметика llama.cpp,
  чужое поле модель не переписывает).
- `/v1/models` = три ID в ЛЮБОМ состоянии: до/после каждого шага
  (снапшоты в 11-cycle-verify.logjsonl) и параллельно во время холодных
  стартов (poller `/v1/models`: 21/21 выборки — все три ID; файлы
  `verify-models-during-{iq3,iq2}.log`). Движко-логи подтверждают: ни одного
  co-residency двух движков — «stopping» старого всегда предшествует
  следующему «starting engine».
- 404-ловушек нет: активный профиль всегда `ninfer`, никакие профильные
  переходы не случаются (снапшот `profile` на каждом шаге).
