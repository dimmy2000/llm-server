# 02 — Драйверная ветка: 615.71.09-p2p или 610.57.04-p2p-v3

Type: grilling
Status: resolved
Blocked by: 

## Question

Какую ветку `aikitoria/open-gpu-kernel-modules` выбрать первичной для
драйверного стека (userland + ядра модули) и какую задокументировать как
фолбэк?

Факты (0010-отчёт, issue #25):
- дефолтная ветка `615.71.09-p2p` (обновлена 2026-09-16): README без
  NVreg-двордов, «How to use» совпадает с планом 0010;
- `610.57.04-p2p(-v2/-v3)` (авг–сен 2026) — старше; на `610.57.04-p2p`
  отчёты висов NCCL (4×3090/5090, vLLM) — нас не касается (NCCL/vLLM не
  гоняем), но маркер зрелости ветки;
- сентябрьский опыт пользователя — на 615.x; эффект 610→615 (prefill
  llama.cpp −14%) — это эффект версии драйвера (H2), а не ветки;
- ядро `7.0.0-38-generic`: сборка open-модулей NVIDIA под него никем не
  задокументирована — риск одинаков для обеих веток.

Рекомендация: `615.71.09-p2p` — первичная (самая свежая, дефолтная,
совпадает с планом 0010); `610.57.04-p2p-v3` — задокументированный фолбэк.

Решение: зафиксированный выбор первичной + фолбэк, от которого строится
«Смена драйвера на 615.71.09».

## Answer

Решено (grilling-сессия 2026-10-10, по одному решению за раз):

| Ось | Решение |
|---|---|
| Первичная ветка | `615.71.09-p2p` (HEAD c8bff54) |
| Фолбэк | `610.57.04-p2p-v3` (461d638, 2026-09-04) |
| Если срабатывает фолбэк | весь стек (userland 610.57.04 + v3-модули) + **пересъёмка vanilla-baseline на 610.57.04** (вариант B: H2 остаётся изолированной) |
| Триггеры фолбэка (тикет 04) | сборка 615-модулей не прошла / после `iommu=pt`+reboot матрица CNS-NS / `simpleP2P`-ошибки данных после проверки iommu=pt/BAR1/dmesg |
| Не триггеры | полоса <10 GB/s (ACS/BIOS, туман H8/H6); выпадение после ребута (тикет 07, H9); вися типа NCCL (vLLM вне скоупа) |
| Терминал | v3 тоже не даёт P2P на 7.0 → полный откат на apt 595.99.02, GRUB без `iommu=pt`, карта закрывается «не внедрять: несовместимость с kernel 7.0» |

**Обоснование.** Факт, которого не знал отчёт 0010: issue #24 форка —
патченные модули на kernel 7.0.0 дают P2P **CNS** (595.58.03-p2p, Proxmox
7.0.0-3-pve; подтверждено на Ubuntu 26.04, 2026-05). Закрыт 2026-08-13:
владелец указал `610.57.04-p2p` — «nvidia's kernel 7.0 compat fixes»,
репортёр подтвердил, что P2P завёлся. Структура веток — единый trunk:
`615.71.09-p2p` = база `610.57.04` (e4a5faa, 7.0-compat) + апгрейд исходников
`615.71.09` (61dcc93, 2026-09-09) + те же 4 патч-коммита, что в
`610.57.04-p2p-v3` (shared console mapping, hugepage host-reg, mixed-gen
BAR1 P2P, libcuda-патч — последний только для смешанных пар, не наш случай).

1. **615 первичной**: 7.0-фикс в ней уже есть (он в старшей базе);
   единственная незаверенная дельта — апгрейд базы до 615.71.09, который
   ровно таков же риск, как vanilla-сборка 615 в тикете 03 (если vanilla 615
   не соберётся под 7.0, план умирает на 03 независимо от ветки). Фолбэк на
   610.57.04 вместо этого замутнил бы дельту тикета 05 конфаундером
   даунгрейда 615→610 (сентябрь: prefill −14% на 610→615). Сентябрьский опыт
   пользователя — на патченном 615.x (D2D 8.9 GB/s).
2. **v3 фолбэком**: тот же патч-слой, что в первичной (фолбэк меняет только
   базу — один переменный), база подтверждена на 7.0 в #24. Plain
   `610.57.04-p2p` подтверждён чуть сильнее, но тогда сдвигаются и база, и
   патч-слой — диагностика мутнее. `610.57.04-p2p-v2` — иная
   экспериментальная линия (display-aware BAR1 sizing, fail-closed), не та,
   на которой владелец сошёлся с 615-веткой.
3. **Вариант B (пересъёмка vanilla 610)**: фолбэк — это всегда полный стек
   (версии модулей обязаны совпадать с userland/GSP), поэтому vanilla-
   baseline тикета 03 (на 615.71.09) перестаёт быть осью сравнения.
   Пересъёмка vanilla 610.57.04 (vanilla open-модули без P2P-патча, reboot,
   бенчи тикета 01) даёт дельту P2P = (610→610-p2p) минус (595→610);
   дополнительный build-риск ~нулевой (тот же source, что v3), цена — один
   maintenance-цикл.

**Проверенные факты**: `nova_core` (драйвер kernel 7.0 из issue #24, который
авто-биндится к GPU) на хосте **отсутствует** (`modinfo nova_core`: not
found) — чёрный список не нужен. README обеих веток — одна и та же процедура
(GRUB `iommu=pt`, userland `.run --no-kernel-modules`, `./install.sh`,
reboot); NVreg-дворды не требуются.
