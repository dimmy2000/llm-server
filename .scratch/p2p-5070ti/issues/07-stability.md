# 07 — Стабильность: reboot, ранбук обновления ядра, 24h soak (H9/H10)

Type: task
Status: resolved
Blocked by: 05, 06

## Question

Эксплуатируемо ли P2P на этом хосте (не «однажды заработало»)?

Проверки/работы:
- reboot: после перезагрузки P2P поднимается сам (прецеденты: на Proxmox
  «не заводится» (чат 27036), на Tyan «само поднялось» (27038)) — два
  reboot-цикла;
- ядро: HWE-обновление ядра → патченные модули не пересобираются сами;
  решить режим — пин ядра vs ранбук «пересобрать nvidia-модули после
  обновления» (заметка vladie: «P2P выпадает → чистить /lib/modules и
  ставить заново») — и задокументировать в репо;
- 24h soak под нагрузкой (продакшн-ротация NInfer/llama), мониторинг
  `llm-*` (nvidia-smi-exporter): Xid-ошибки, ошибки CUDA, свободная VRAM;
- красная линия: min free GPU1 ≥ 512 MiB под пиковой нагрузкой после смены
  драйвера (H10; на текущем профиле до смены 264–278 MiB — тикет 13).

Решение: задокументированный ops-режим (ранбук в репо) + результат soak.

## Answer

Эксплуатируемость P2P на этом хосте подтверждена; итог по фактам (полный
24h-soak не гонялся — свернут по решению 2026-10-11, результат — на
частичном прогоне 5.27 ч).

**H9a — P2P переживает reboot (подтверждено, 2 цикла):** после каждого из
двух ребутов `topo -p2p r` = OK/OK, `simpleP2P` = Test passed без ручных
действий; движок стартует `p2p on` + `captured all-reduces: copies`. Стек
байт-в-байт до/после (sha256 модулей, драйвер 615.71.09, vermagic, cmdline
`amd_iommu=on iommu=pt`). Артефакты: `assets/07-stability/pre-reboot-1.txt`,
`post-reboot-1.txt`, `post-reboot-2.txt`.

**H9b — режим ядра (решено):** HWE-ядро не пинится; после каждого обновления
ядра патченные модули пересобираются по ранбуку. Ранбук и инструменты в репо:

`scripts/nvidia-p2p/{rebuild-modules.sh,p2p-verify.sh,p2p-snapshot.sh,soak.sh}`.
Cross-ядровая пересборка проверена (`--kernel 7.0.0-34-generic` → vermagic
`7.0.0-34-generic`, 12.9 с) и возвращена на `-38`. Реального HWE-обновления в
apt на момент закрытия нет — ранбук отработается при первом.

**H9c — soak (частичный, 5.27 ч):** P2P-стек **стабилен под непрерывной

`errors.log` пуст): `assets/07-stability/soak-24h/`.

**H10 — красная линия (решение):** min free GPU1 = **19 MiB** (на пике
90k-prefill), GPU1 < 512 MiB в 30.7 % рантайма; GPU0 держится (min 1015 MiB).
**Принято решение: нарушение красной линии 512 MiB зафиксировать как
документированный регресс текущего ninfer-профиля**; оговорка — выброс может
быть связан с фоновыми задачами, не связанными с инференсом, в процессе
прогона. Механизм преимущественно профильного уровня (удержанные KV длинных
диалогов в device-state слотах + периодические 90k-prefill-ы съедают
свободную VRAM дисплейной GPU1 ниже `--vram-headroom-mib 640`), а не P2P —
дальнейшая судьба профиля в ведении ninfer-тикетов (13 / новый).

**Итог по тикету:** P2P на этой машине эксплуатабелен — после ребутов
поднимается сам, под нагрузкой стабилен (0 ошибок), обслуживание драйвера
закрыто ранбуком. Ограничение VRAM-красной линии текущего профиля принято как
регресс с задокументированной оговоркой. Тикет закрыт; разблокирован 08.
