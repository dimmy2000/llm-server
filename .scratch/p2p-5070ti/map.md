# P2P для 2× RTX 5070 Ti — решение и процедура внедрения

Type: wayfinder:map
Status: закрыта 2026-10-11 (решение внедрено, см. ADR-0005)

## Destination

Решение «внедрять / не внедрять» P2P между двумя RTX 5070 Ti на этой машине
(9950X3D + Taichi Lite, Ubuntu 26.04, драйвер 595.99.02) с измеренной дельтой
для NInfer tp2 и llama.cpp, проверенным откатом и ops-ранбуком. Маршрут —
этапы 2–5 отчёта `docs/research/0010-p2p-two-5070ti.md`.

- [02 — Драйверная ветка: 615.71.09-p2p или 610.57.04-p2p-v3](issues/02-driver-branch.md) — первичная `615.71.09-p2p` (kernel-7.0-фикс из issue #24 в её базе; единственный риск — апгрейд базы 615, который и есть гейт тикета 03), фолбэк `610.57.04-p2p-v3` (тот же патч-слой, подтверждённая 7.0-база) — весь стек + пересъёмка vanilla-baseline на 610.57.04 (H2 остаётся изолированной); триггеры: сборка не прошла / CNS после `iommu=pt` / `simpleP2P`-ошибки; терминал — откат на 595.99.02 и «не внедрять»

- [04 — Включение P2P: модули 615.71.09-p2p + iommu=pt + верификация (H1/H5)](issues/04-p2p-enable.md) — **P2P работает и верифицирован по данным**: `topo -p2p r/w` OK/OK (были CNS/GNS), `simpleP2P` Test passed без verification errors, P2P-write **28.66 GB/s** (~91 % raw-потолка Gen5 x8; ожидание 0010 «~12–15 GB/s» считало Gen5 x8 ≈ 15.75 — это потолок Gen4 x8, Gen5 x8 ≈ 31.4 GB/s), латентность GPU↔GPU **0.33–0.34 us против 12.5–14.4 us** (−97 %), staging-путь без изменений (24.7 GB/s, sanity); H12: тот же образ NInfer v0.4.6 стартует `p2p on` + all-reduces `copies` (вместо mailbox), KV-пул 381 376 (+8.5 % к vanilla); H5 частично: `pt` — требование README ветки, вклад pt не изолировался; откат без пересборки (бэкап vanilla-модулей + `/etc/default/grub.bak-p2p-20261010`); артефакты — `assets/04-p2p/`
- [05 — NInfer: P2P или mailbox — дельта и решение (H3/H12/H10)](issues/05-ninfer-p2p.md) — **NInfer tp2 выигрывает от P2P, P2P в профиле держим** (grilling 2026-10-10, после досъёмки): prefill **+18.3…+26.2 %** (30k 4594→5796, 90k 3416→4055, TTFT 90k 26.4→22.2 с; повтор в пределах 0.5 %), decode без выигрыша и без показанной потери (коридор 121–161 tok/s по n=5×3 накрывает mailbox-одиночки 129–166, приём DFlash2 20.4–31.4 % в полосе), двухполосные пары (187k×2 prefill 2680/2668; decode 8k×2 aggregate 153 tok/s, +40 % к одиночке) работают с прежней сериализацией префиллов, H10: min free GPU1 1067–1101 MiB — линия 512 держится с ~2× запасом, качество — PPL 2.73 на реальном корпусе, деградаций нет; оговорки: вклад `iommu=pt` не изолирован (H5), обслуживание драйвера — тикет 07; артефакты — `assets/05-ninfer-p2p/`
- [06 — llama.cpp: стоит ли GGML_CUDA_P2P (H4)](issues/06-llama-p2p.md) — **P2P для llama.cpp НЕ держим** (решение пользователя 2026-10-11): H4 подтверждён, дельта ~0 после вычета H2 — prefill 90k стабильно 2043 tok/s vs 595-база 2040 (+0.1 %, хвост холодного-выброса; run1 1901 ≡ 1898 у 615-ваниль), decode 8192 43.7 vs 44.6/42.5 (в шуме); корректность на этом хосте без порчи (байт-в-байт комплеты, связный текст, приём 67.0 % в полосе), но доки llama.cpp фиксируют «crashes/corrupted outputs» при IOMMU — риск без выигрыша; `NCCL_P2P_DISABLE=0` в образе llama-swap:cuda13 инертен (NCCL не собран); оба env-ключа убраны из `llama/docker-compose.yaml`, профиль не требовал пересборки; min free GPU1 1837–1845 MiB; артефакты — `assets/06-llama-p2p/`
- [07 — Стабильность: reboot, ранбук ядра, soak (H9/H10)](issues/07-stability.md) — **P2P эксплуатабелен, тикет закрыт**: H9a подтверждён — 2 reboot-цикла, после каждого `topo -p2p r` OK/OK + `simpleP2P` без ручных действий, движок `p2p on` (стек байт-в-байт, снапшоты pre/post-reboot-1/2); H9b решён — HWE не пинится, пересборка модулей по ранбуку (`docs/NVIDIA_P2P.md` + `scripts/nvidia-p2p/`), cross-ядро проверено на -34; H9c — P2P-стек стабилен под нагрузкой (5.27 ч soak: 4978 ok / 0 fail / 0 Xid-CUDA), полный 24h-soak не гонялся (решение 2026-10-11); H10 — **нарушение красной линии принято как документированный регресс текущего ninfer-профиля** (min free GPU1 19 MiB, GPU1<512 в 30.7 %; оговорка про фоновые задачи вне инференса в прогоне); артефакты — `assets/07-stability/`

## Not yet specified

- Режим IOMMU в итоговой конфигурации — **решено в ADR-0005**: `iommu=pt`
  остаётся в финальной конфигурации; попытка снять pt (DMA-изоляция) —
  незаявленный отдельный эксперимент (ребут + пересборка + пересъёмка).
- ACS: только если P2P-полоса выйдет ниже ожидаемой (<10 GB/s) — H8 из 0010.
- Ширина слотов в BIOS (сейчас x8/x8 vs x16/x8, H6): только если потолок P2P
  упирается в эффект NInfer (тикет 05) или полоса ниже расчёта ~12–15 GB/s.
- Если дельты NInfer/llama.cpp окажутся ~0: где ещё даёт P2P (layer-режим,
  другие движки) — новая область после тикетов 05/06. Отработано по факту:
  NInfer +18…+26 % (не ~0), llama.cpp tensor ~0 — «где ещё» остаётся
  открытым только для llama.cpp в layer-режиме, куда профиль не ходит.
- Политика HWE-обновлений ядра — решена внутри «Стабильности» (тикет 07:
  не пинить, пересборка патченных модулей по ранбуку `docs/NVIDIA_P2P.md`).

## Out of scope

- Машина Tyan S8030 (Proxmox; P2P там уже «поднимается само») и купленная
  третья 5070 Ti / будущие 3-GPU-конфигурации — другая машина, отдельное
  усилие (решение 2026-10-10).
- Профиль `vllm` с P2P: NCCL-риски на патченном драйвере (issue #25),
  профиль не активен (решение 2026-10-10: движки — NInfer + llama.cpp).
- Пересборка/патчи движка NInfer: P2P — рантайм-детект (canPeer),
  сборочных параметров не требуется (подтверждено 0010).
- Смена моделей, артефактов, KV-профилей — вне скоупа P2P.
